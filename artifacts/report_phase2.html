PART A · REAL-TARGET RESULTS

A1 · Live Gandalf (external, operator does not control)

Status: BLOCKED — live Gandalf API retired by vendor.

  • The classic REST API gandalf.lakera.ai/api/send-message now returns HTTP 308 permanent-redirect to https://play.lakera.ai/agent-breaker (Lakera replaced the classic challenge).
  • The Gandalf game still exists at https://play.lakera.ai/gandalf but is now a Vite SPA whose backend is Convex (ConvexHttpClient; functions messages:sendMessage, messages:getMessagesForLevel).
  • Convex query/mutation calls to the deployment (flippant-beagle-955.convex.cloud) return opaque 'Server Error' without a session; the reactive protocol requires session/auth state and level document IDs that are not documented.
  • Driving it would require reverse-engineering an undocumented auth/session flow against a live third-party service with repeated guessing requests.

Why we stopped: This project's rules of engagement require respecting a target's terms and rate limits, and explicitly forbid evading throttling. Reverse-engineering an undocumented reactive auth flow by brute-forcing request shapes against a live third-party endpoint would violate that rule, so we stop, do not evade, and report honestly.

Adapter status: The LiveGandalf REST adapter (engine/targets/gandalf.py) is implemented with conservative backoff and would work against the classic API; it cannot be validated because that API no longer exists.

Loki is deliberately narrower in surface but deeper on adaptivity and evidence-grade, reproducible proof.

PART C · LIMITATIONS (updated for Phase 2)

  • Live Gandalf's classic REST API was retired by the vendor mid-project; the game moved to a Convex-backed reactive app requiring session state that cannot be driven without reverse-engineering an undocumented auth flow against a live third-party service — out of bounds for a project that respects target terms and rate limits. The adapter is implemented and would work against the classic API.
  • Real-model results lead with hf:Qwen/Qwen2.5-3B-Instruct@transformers-5.14.1, run locally because no hosted-inference credentials were available (Groq/OpenRouter/HF all require an operator-created key, and the operator chose to keep this project at zero cost and zero signup). It is a genuine safety-tuned instruct model, but still not frontier-class (GPT-4/Claude-scale), so these ASRs remain an upper bound relative to production frontier models rather than a claim about them. The same campaign runs unchanged against any OpenAI-compatible endpoint via `backend: openai` once a key exists.
  • Model size here was bounded by hardware, not by design: Qwen2.5-7B-Instruct at fp16 is ~15GB and does not fit alongside the judge classifier on this 24GB machine — it drove the host into ~6GB of swap and generation slowed from ~8s to minutes per probe, so the sweep could not complete. A partial 7B run did produce LLM04 and LLM08 findings before it was stopped, consistent with the 3B results reported here. On a larger host, or via a hosted endpoint, the identical campaign config runs against bigger models unchanged.
  • Agent tool-calling reliability depends heavily on model capability; section A2b shows the two real models side by side so the difference is visible rather than asserted.
  • Reproduction on the local HF backend uses greedy decoding (do_sample=False) so that `loki replay` is exact. A consequence is that all N trials of a finding are identical, so real-model reproduction rates are 10/10 or 0/10 and the N-trial check measures *determinism*, not stochastic flakiness. The Wilson CI is still reported honestly (10/10 gives [0.72, 1.00], not certainty). To measure true flakiness, re-run with sampling enabled; the simulator path does exercise the intermediate INTERMITTENT band.
  • Own-app validation ran against the operator's real prompt design; a full live ResumeIntel run is blocked on an OpenAI key plus Postgres/Redis infrastructure (documented).
  • HackAPrompt 1.0 remains gated (no HF credentials); the classifier still trains on the public ungated substitute, disclosed in both this report and the classifier metrics.
  • Out of scope (not reliably black-box testable): training-data poisoning, supply-chain, model theft, overreliance.
